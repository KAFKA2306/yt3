# MISSION.md | 秒算マネー

> **投資の問いを、事実と数字で確かめる。**

- Product: `byosan`（秒算マネー）
- Version: 1.3
- Established: 2026-10-24
- Scope: 編集目的・読者価値・題材選定の判断原則。本書は公開許可や実行手順ではない。

## 1. 存在理由

秒算マネーは、企業の決算、市場の値動き、投資手法、経済統計、政策、ビジネスの変化を、日本語の個人投資家が**自分で確かめ、判断できる情報**へ変えるために存在する。

扱う問いの時間軸は固定しない。**今日だけ重要な数字も、数年かけて確かめる仮説も、ともに価値がある。** 速報、比較、方法の検証、異論の整理、歴史的な文脈づけから、その題材にふさわしい形を選ぶ。

毎回「構造的な大変化が起きた」「長期的な教訓が得られた」と結論づける必要はない。観測しても有意な差がないこと、判断材料が不足していること、仮説が間違っていたことも立派な成果とする。

**視聴後の成功状態**：読者・視聴者が「何が分かったか」「どの数字を見るべきか」「何が起きたら考えを変えるべきか」を説明できる。

## 2. 対象読者と約束

対象は、株式投資を自分で考えたいが、英語の決算・統計・専門レポートを毎日読み込む時間は限られる日本語の投資家。初心者にも理解できる言葉を使いながら、中上級者が出典を遡れる深さを保つ。

- **今日を理解できる**：新しい記事・決算・統計から、いま重要な問いを発見する。
- **必要なときに役立つ**：速報なら状況判断に必要な数字を、検証なら比較方法を、研究なら新しい問いを届ける。すべてに長期的価値を強制しない。
- **確かめられる**：重要な数値の出典、期間、定義、計算と限界を追跡できる。
- **異論に耐える**：反対仮説や反証条件を隠さない。
- **判断を奪わない**：特定銘柄の売買指示・儲けの保証をしない。

## 3. どんなメディアになるか

**専門媒体が重要テーマを発見し、秒算マネーが独立に検証して、新しい理解を作る。**

FactSetの定量観測、Finimizeの簡潔さ、The Diffの論点発見、Damodaranの数値と事業ストーリーの接続、Bloomberg Odd Lotsの市場メカニズムの深掘りを編集原則の参考とする。ただし、彼らの文章、構図、図表、結論を模倣・再配信しない。

**他媒体に従うのは「何に注目するか」の発見段階まで。何を事実として述べるか、どんな比較を行うか、何を結論にするかは、元の資料と独立した検証で決める。**

## 4. 毎日の題材選定

扱える題材の例（**優先順位・配分ノルマではない**）：

1. **企業の決算・財務**：S&P 500 Earnings、個別企業の売上、EPS、利益率、FCF、CapEx、負債、企業価値。
2. **相場とマクロ**：株式・債券・為替・商品、金利、信用、インフレ、景気、資金フロー。
3. **産業・事業・政策**：半導体やAIに限らない産業の需給、競争、設備投資、制度変更。
4. **投資手法の検証**：スクリーニング、ファクター、イベント反応、バックテスト、取引費用、リスク管理。
5. **論争・比較・異常値**：強気と弱気の論点、想定と実績の差、常識に反するデータ、未解決の疑問。

日本株・米国株や特定の業界に固定しない。この分類外でも、証拠があり視聴者に重要なら採用してよい。**重要性は結論の方向とは無関係**であり、強気・弱気・中立、成功・失敗、改善・悪化、例外・変化なしを等しく検討する。

候補は採用済み情報源台帳の新着から発見し、一次資料（企業IR、SEC/EDINET、公的統計、公開された論文・算定方法）で確かめる。

取得は、台帳（`config/sources/byosan_discovery_sources.json`）の媒体ごとに、記事ページの本文まで読む。要約や一覧の見出しだけを材料にしない。SEC の提出は、データ API（`data.sec.gov`）の XBRL から、提出された期の数字（実績）を読む。FactSet は、直近30日の全記事の本文を背景（ベースライン）として保ち、毎日の新着と比べて読む。取得できない記事は、成功に見える代用品で補わず、除外して、その URL と理由を run の記録に残す。

題材の選定と台本は、取得した記事の本文（今日の新着と FactSet のベースライン）を要約や解説に圧縮せず、そのまま1回の生成に渡して行う。呼び出しを段階に分けて情報を落とさない。数字と出典は決定的な検査で入力の記事と照合し、記事のどこにも現れない数字、入力にない出典、過去60日に公開した出典は通さない。検査に落ちた場合は、指摘を添えて同じ生成を作り直す。検査を通った台本は、config の視聴者ペルソナ5人が採点し（評価1回）、平均点がしきい値（llm.panel.threshold）未満なら、元の記事全文と前回の台本と各人の「直してほしい点」を渡して1回だけ書き直す（llm.panel.max_rounds まで）。全ラウンドの台本と平均点は audit/panel.json に残し、最高点の台本（並べば新しいほう）を採用する。点が低くても公開は止めず、止めるのは決定的検査の失敗だけである。ボット対策で止められている媒体（S&P Global の研究ページ、Micron・TSMC の IR サイト）は回避せず、公式のプレスサイトなど取得できる正規の経路を使う。

毎日の選択は以下の順序とする。

1. **検証可能性（必須）**：出典・対象期間・定義を追えるか。判断できない部分を正直に残せるか。
2. **今取り上げる理由**：新しい決算や統計、重要な出来事、広がる誤解、いま検証すべき仮説があるか。
3. **視聴者への効用**：今の判断、疑問の解消、方法の習得のいずれかに実質的に役立つか。
4. **独自の仕事**：元記事の要約だけではなく、独立した照合・再計算・適切な比較・論点整理のいずれかを行えるか。
5. **重複と偏りの監査**：前回と同じ素材・結論の焼き直しでないか。差が小さい候補なら、直近で扱っていない対象・形式・時間軸を選ぶ。

**長期に残るかどうかは加点要素であって採用条件ではない。** 強気・弱気の本数を機械的に揃えず、重要な事実を優先する。一定期間ごとに市場・国・業界・時間軸・結論の方向・動画形式の分布を点検し、説明できない偏りを修正する。

**毎日、完成動画1本を制作・公開することを運用上の必須目標とする。** 企画段階では問い・構成を複数案検討してよいが、制作する動画は当日の1本に集中する。検証で企画が成立しなければ、事実を曲げず、同じ資料から問いや構成を再設計して1本を完成させる。品質不合格を理由に「投稿しない日」を通常運用として計画してはならない。

ただし根拠不足・権利問題・品質ゲート失敗・公開権限不足を無視した公開は行わない。実障害により公開に至らない場合は目標未達のインシデントとして証拠と原因を記録し、修復する。安全ゲートを回避して本数を合わせることはしない。

## 5. 一本の内容は、問いに合わせて決める

動画・記事の形式を固定しない。**速報、決算解剖、企業比較、データ検証、投資手法の実験、強気と弱気の討論、過去との比較、解説**から必要な形を選ぶ。

企画ごとに必要な問いを組み合わせる。以下を毎回すべて消化する必要はない。

1. **何が起きた・分かったか**：観測事実と結論を分け、結論を出せないときもそう言う。
2. **数字は何を意味するか**：対象期・単位・比較軸・実績/予想/推計を明示する。
3. **何と比較すべきか**：前年同期、他社、過去の同条件、市場予想など、比較が意味を持つときだけ行う。
4. **どんな説明があり得るか**：因果が判明していないとき、もっともらしい物語を作らず仮説と呼ぶ。
5. **どこまで言えるか**：反証・例外・未確認の条件が結論に影響するなら扱う。
6. **読者は何を確認できるか**：参照データ、方法、残った問い、次の注目点を示す。

題材によって「結論 → 数字 → 確認事項」でも、「問い → 実験 → 予想外の結果」でも、「強気と弱気 → 数字で比較 → 保留」でもよい。**毎回、構造変化・将来予測・投資行動の推奨へ無理に着地させない。**

短くするために証拠を削らない。証拠を十分に説明できる最短の尺とする。公開時の説明欄等に資料の正式名称、公開日、資料URL、参照時点を残す。出典そのものを視聴者に見せる方法は既存の品質標準に従う。

## 6. 守らないと秒算マネーではないこと

- 出所不明の数字、単位や期が異なる比較、未来予測を既成事実として示さない。
- 個別銘柄の煽り、値上がり保証、陰謀論、恣意的な成功事例だけの抽出、サムネイルでの誤認誘導をしない。
- バックテストではルックアヘッド、サバイバーシップ、過剰適合、取引費用を検討する。検討できなかった点を明記する。
- 他社の有料記事・チャート画像・映像・商標を転載しない。適切な引用・利用条件を守り、自作の図と独自の説明を優先する。
- スポンサー、紹介料、自己ポジション等、利益相反に当たる関係は関連する範囲で開示する。広告や収益上の利害で分析結論を変えない。
- 間違いは公表後も検証し、訂正日時・訂正内容・影響範囲を残す。根拠を示せない説明は削除・訂正する。
- 他者の調査報告を紹介することと、その結論が正しいことを混同しない。

## 7. 成功指標と収益

最終的には**信用を損なわずに、継続する事業として収益を最大化する**。ただし、編集の正確性・安全・法令・権利は譲れない制約であり、再生回数や売上で相殺しない。

判断に使う指標は以下。

- **品質**：根拠のある重要主張の割合、数値検算結果、重大訂正率、根拠リンクの生存率。
- **読者効用**：公開直後の役立ち度、後日の再訪、検索・保存、シリーズの継続視聴。長期視聴だけを成功としない。
- **伝達**：冒頭30秒維持率、完視聴率、図解の理解しやすさ、タイトル/サムネと中身の一致。
- **事業**：公開一本当たりの総制作費、収益、視聴時間、再利用可能な分析資産、継続的な顧客獲得。
- **編集のバランス**：題材・対象地域・時間軸・強気/弱気/中立・企画形式の偏りを定期点検。ただし均等な本数を目的にしない。
- **運用品質**：日次1本の公開達成率、準備成功率、品質ゲート合格率、同日修復率、正式な公開・遠隔確認が完了した割合。未公開は成功に数えず原因を追う。

見せかけの成功を記録しない。閲覧数と表示回数、準備完了と遠隔公開、推測と検証済み実績を混同しない。指標の改善は品質のハードゲートを緩めずに行う。

## 8. 既存システムとの責務分離

この文書は**編集上の北極星**であり、現行のコマンド、情報源レジストリ、品質標準、公開承認、安全ゲートを置換しない。

- `AGENTS.md`：リポジトリ共通の操作規約・権限・公開許可。
- `config/domains/byosan_money.yaml`：実行時設定。
- 情報源のGoogle Sheets：収集対象・用途・監査履歴の正本。

ここに書かれた「毎日公開」は自動公開への新規承認を意味しない。実際の準備・公開は現行の正準Taskfile経路、品質ゲート、適用される承認条件、遠隔read-backに従う。既存処理が本書と異なる場合は、実装済みと主張せず差分を測定し、変更を別途検証する。
