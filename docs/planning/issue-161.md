## 2. 動画の主張

- コアメッセージ: 企業開示は「読む資料」ではなく特徴量にできる。
- 変換の流れ: 研究 → データソース → 特徴量 → イベント → 目的変数 → 検証 → 売買シグナル
- 冒頭フック: 「有報を読んで終わっていませんか？ AI金融研究では、文章そのもの、提出したという事実、文章の前年差まで投資データになります。」
- 結論候補: 「AI投資で最初にやるべきことは、明日の株価をAIに聞くことではない。企業が今日出した情報を、昨日まで存在しなかった特徴量に変えることだ。」

動画で断定しないこと: 研究の効果量・再現性は予稿と検証結果で確認するまで主張しない。「学術研究の観点」と「自分の検証結果」を分けて話す。

## 3. 主役トピックの仕様

### 3.1 #13 大量保有報告書 × 株式リターン

- 見る項目: 取得者、初回か変更か、保有比率、保有比率の変化量、保有目的、提出日時
- リターン窓: 1 / 5 / 20 / 60 営業日
- データ経路: EDINET 大量保有報告書 → filer / issuer / filing timestamp / initial-or-change / ownership / delta / purpose → 株価結合 → AR / CAR → 条件別検証 → シグナル候補
- 注意点:
  - 提出日時を基準日にし、公衆に利用可能になった時点以降のみ使う（look-ahead 防止）
  - 上場廃止・組織再編による欠損を除外せず記録する（survivorship）
  - 株式分割・配当などの corporate action で株価を調整する
  - 売買コストを差し引いたリターンも併記する

### 3.2 #16 配当政策テキスト × 減配リスク

- 見る文言の例: 累進配当、原則として減配しない、DOE、安定配当、配当方針の前年差
- データ経路: 有報 → 配当政策節の抽出 → text features / embedding → 将来減配ラベル → walk-forward 検証 → 減配 risk score
- 注意点:
  - 節抽出器は有報の版（訂正報告書の扱いを含む）を固定して再現可能にする
  - 減配ラベルの定義（期末 vs 中間、特別配当の扱い）を先に決める
  - 学習期間より後の情報を特徴量に入れない
