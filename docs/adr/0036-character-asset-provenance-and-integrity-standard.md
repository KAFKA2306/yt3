# ADR 0036: Character Asset Provenance & Integrity Standard

## 📝 プロベナンス表示 (Claim Provenance)
- **VERIFIED**: Humanity Observatory 制作時において、キャラクター資産（雨晴はう、もち子さん等）の管理がリモート参照や曖昧なパスに依存しており、実行環境の再現性とライセンス整合性が担保されていない事実を特定。
- **OBSERVED**: ユーザーにより定義された 10 項目の「Character Asset Audit Spec」を特定。
- **INFERRED**: キャラクターの「正しさ」を証明するには、名前の指定だけでなく、ローカル資産のハッシュ、ライセンス、およびソースURLを紐付けた「資産プロベナンス」の機械的検証が必要である。

## 状態
決定済み（Accepted）

## 文脈
「リモートURLは証拠ではない。」
キャラクター素材がローカルに存在しない、あるいはハッシュ化されていない状態は、ゼロトラスト監査における深刻な脆弱性である。本 ADR は、キャラクター資産を物理的に隔離し、その真正性とライセンス遵守を数学的に証明するための「資産プロベナンス標準」を定義する。

## 決定事項

### 1. 資産管理の鉄則 (Philosophy)
- **ローカル再現性の強制**: すべての参照資産はローカルに実在し、ハッシュ（SHA-256）によって整合性が証明されなければならない。
- **ホットリンクの禁止**: 外部サーバーへの直接リンクや、プロベナンス（入手元証明）のない手動コピーを厳禁とする。

### 2. 決定論的ディレクトリ構造 (Required Layout)
資産は以下の構造で厳格に管理する。
- `assets/characters/<character_id>/portrait/` : 立ち絵・ポートレート
- `assets/characters/<character_id>/icon/` : アイコン
- `assets/characters/<character_id>/license/` : ライセンス条文・許諾証明
- `assets/characters/<character_id>/metadata.json` : プロベナンス・メタデータ

### 3. 機械検証可能な監査項目 (Machine Verifiable Checks)
| ID | 監査内容 | 証拠 (Evidence) |
| :--- | :--- | :--- |
| **ASSET-001** | ファイルの実在 | `test -f` による存在確認 |
| **ASSET-002** | 整合性証明 | `sha256sum` と `metadata.sha256` の一致 |
| **ASSET-003** | 入手元証明 | `source_url` および `license_url` の記録 |
| **ASSET-004** | 正準パス検証 | 指定されたディレクトリレイアウトへの適合 |

### 4. ワークフロー制約 (Workflow Implementation)
- レジストリにキャラクターが登録された場合、自動的に「資産取得タスク（Acquisition）」が生成されなければならない。
- 公開（Publish）前にすべてのローカル資産が揃っていない場合、監査 FAIL としプロセスを停止する。

## 帰結
- **利点**:
  - キャラクター使用のライセンス情報と取得元の「追跡可能性（Traceability）」をメタデータによって保証できる。
  - 開発環境を移動しても、ハッシュによって「全く同じバイナリ素材」が使われていることを検証できる。
- **限界**:
  - 記録された `source_url` が公式なものであるか、ライセンスが妥当であるかといった「法的な安全性そのもの」は機械監査不能であり、別の信頼層（Human Review等）が必要である。
- **代償**:
  - 新規キャラクター導入時に、手動ダウンロードとメタデータ作成のオーバーヘッドが発生する。
  - 素材の差し替え時にハッシュの更新が強制される。
