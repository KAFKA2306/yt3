# ADR 0027: 自己進化データベース（Schema v2）の採用

## ステータス
**Accepted**

## コンセプト（マスターへっ♪🌸）
マスター、お疲れ様だよっ！動画が「ただ作られる」だけじゃなくて、「なぜそうなったか」「次はどう変異すべきか」を記憶するための、最強のデータベース（進化する脳細胞！）を設計・採用したよっ！🎀✨

## コンテキスト（背景だよぉ♪）
これまでのファイルベースのログ管理では、数世代にわたる「戦略の変化」や「視聴者の反応との因果関係」を横断的にクエリすることが難しかったんだ。特に、マンネリ化（コラプス）を防ぐためのエントロピー監視や、自律的なパラメータ修正（変異）を安全に行うためには、厳格なスキーマを持つリレーショナル・データベースが必要だったの。

## 決定事項（設計のキモだよっ！🏆）
以下の18テーブルにおよぶ、**自己進化型リレーショナル・スキーマ**を `db/evolution.db` (SQLite) に実装したよ！

1.  **runs (基盤)**: すべての出発点。ハッシュ値で整合性をガチガチに守るよ！
2.  **raw_artifacts (保存)**: 生の証拠をそのままハッシュ付きで保管。改ざん許さないんだからっ！
3.  **strategy_genomes (遺伝子)**: フックパターンや感情曲線など、動画の「性格」を定義するコア。
4.  **collapse_signals (監視)**: マンネリ化の兆候（エントロピー低下）を即座にアラート！
5.  **mutation_plans (変異計画)**: どこを変えるか、どのスロットを凍結するかを安全に管理。
6.  **evolution_events (進化履歴)**: 変異の前後で、視聴維持率がどう変わったかの物語を記録するよ♪
7.  **audit_checks (厳格監査)**: ラウドネスや数値正確性など、34項目以上の関門をすべてログ化！
8.  **script_segments (ミクロ解析)**: ダイアログ1行単位の緊張感や固有名詞密度を数値化。

## コンシークエンス（結果どうなったかだよっ！✨）
*   **追跡可能性の爆発的向上**: 「なぜ5月17日のランはブロックされたの？」という問いに、SQL一発で「前日とのフック類似度が75%だったからです！」って即答できるようになったよ！
*   **自律的な自己修正が可能に**: 崩壊シグナルを検知して、自動的に `mutation_plans` を立てるための基盤が整ったの。
*   **Zero-Fat 監査の実現**: 不要な中間ファイルを消しても、DBに「真実」が正規化されて残っているから、安心してクリーンアップできるんだよっ♪
